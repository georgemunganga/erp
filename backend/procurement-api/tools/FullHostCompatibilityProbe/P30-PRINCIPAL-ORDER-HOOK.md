# Private P30 principal order HTTP proof (source only)

The existing `--principal-approvals` host probe accepts the exclusive opt-in
`P30_HTTP_VERIFY_PRINCIPAL_PO=1` only for a newly created, empty PostgreSQL 17
private database named `proc_p30_http_po_*` on the allowlisted Unix socket. Use
`P25_HTTP_OWNER_CONNECTION` and a new protected `P25_HTTP_RESULT` path; the
existing private launcher must provision and own that clone. No production
connection, existing accepted private database, browser fixture, or auth bypass
is accepted as proof.

The P30 branch composes the actual Program host. It requires the genuine
Procurement owning migration, finite execution-role privileges, normal
`IProcurementPrincipalOrderDraftReadiness`, and live metadata capability. It
never replaces readiness with a positive stub. Default-off production options
remain unchanged. The probe first creates a real workerless principal PR with
an independently activated direct method, budget evidence, published rule,
Core approval, and original source pins through the existing P25 HTTP cohort.
It then creates and independently approves a supplier master, PO-specific
spending authority and PO rule through their normal routes.

PO cancellation also reads retained `principal_receiving_sources` to veto a
release after receiving has begun. PO readiness inspects that table's mapped
columns, keys, checks, and foreign keys and requires SELECT in a PO-only
cohort. It does not require receiving INSERT, UPDATE, or the receiving command
capability.

P30 checks the purpose-scoped source and supplier pickers, exact internal
PO draft/reservation, same-key replay and actor-owned GET recovery, unfunded
cancel, funded pending-release and independent manual release confirmation,
retained Finance-recorder branch-scope revocation denial, Core assigned
review/decision, internal issue and separately observed supplier acceptance.
Owner reload asserts two released allocations and one ordered allocation,
original request remaining quantity, immutable evidence/receipts, and no
Finance AP/payment row or employee fixture. All external references in this
cohort are visibly synthetic manual attestations; they are not Finance posting,
supplier transmission, or payment proof.

An additional, separate fresh `proc_p30_http_po_*` clone may set
`P30_HTTP_VERIFY_RETAINED_HISTORY_CANCEL=1` alongside the PO opt-in. This
exclusive owner-only negative cohort redirects a genuine submission's
redundant order ID to another real unfunded draft while retaining the original
funding reference. It requires the normal Cancel API to return 409 without
reservation, receipt, audit, or outbox effects, restores the original ID in
`finally`, and confirms ordinary cancellation afterward. This flag cannot be
combined with normal-cookie serving, receiving, or RFQ cohorts. Without it,
the original three-order PO graph and cookie-owner fixture remain unchanged.

This is a source-only probe until the P30 migration, finite role manifest,
readiness and metadata are integrated and the parent runs the serialized
private PostgreSQL/HTTP rehearsal. Do not claim pass from authored code.
