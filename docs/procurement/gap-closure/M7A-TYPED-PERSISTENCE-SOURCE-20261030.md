# M7A typed persistence source checkpoint

Status: implementation candidate; not compiled, migrated, enabled, or accepted in a native database.

This checkpoint extends the accepted pure commercial and principal-capture contracts. It maps the existing `SupplierBid`/`SupplierBidLine` commercial offer columns plus two append-only Procurement sidecars: outside-contact evidence and quotation versions/owned command receipts. Legacy rows retain capture protocol zero and null offer fields. New captures require protocol two and the full V3 immutable commercial snapshot. The earlier V2 pure evidence reader remains supported; it does not authorize legacy adoption.

The owning Save preparation requires a complete scoped quotation version, exact typed request/snapshot/response, same-bid predecessor and monotonic observation time, existing header CAS, complete active line set, and the exact audit/outbox marker pair. Shared ERP generic audits remain intact. A line-only revision must explicitly mark the existing header modified. Removing a quotation line means marking it inactive, not deleting it. Supplier/invitation/submission-version uniqueness still prevents cancelled-draft recreation; no recreation policy is claimed.

Current quotation actions will use Core identity, explicit grants and existing company/branch scope. Historical employee aliases are attribution only. A later authorized principal may revise/cancel a draft; original command recovery remains private to its original principal and key. Persistence guards do not replace current application authorization or retained M4/approved-demand verification.

Published M4 invitations retain their original shortlist and receipt checks. Ready invitations remain readable without querying the new sidecars. The new `ManualContactRecorded` state requires exact scoped contact evidence tied to the original publication opening, decision, invitation and resulting version. A separate retained projection permits history/cancellation after source cancellation without presenting released demand as currently reserved. Recording contact reports an external interaction; it never sends email or proves supplier submission.

Raw offered amounts retain existing numeric(18,4) columns. Discounts and derived documentary totals use the accepted exact scaled-integer rules and canonical text in the typed V3 evidence; they are not rounded into an invented numeric(38,8) total column. Supplier tax/payment codes remain documentary offers, not verified Core catalog references. Document selections are proposals. Empty attachment sets work; nonempty sets require the future actual enlisted Core use-pin transport, not fabricated verification.

Verification authored in this checkpoint covers actual EF model scope/protocol relationships, shared staging, missing/unbacked effects, legacy mutation denial, M4 contact admission, exact snapshot restoration, malformed/noncanonical evidence, fourteen-decimal discount scale, cross-principal history/recovery and cancelled-source retention. These tests have not run at this source checkpoint.

Remaining gates: compile and execute tests; review the mapped model; genuine EF scaffold/snapshot and generated SQL; native isolated schema/privilege/rollback proofs; owning HTTP action and original-key-first READ/RECORD contract integration; Core permission/branch denial tests; reuse the existing quotation UI with server-owned labels/capabilities; actual cookie/browser and independent owner reconciliation. HTTP source drafts are preserved separately and are not part of this checkpoint. No runtime readiness provider, route activation, production mutation, migration application or whole-module completion is claimed.
