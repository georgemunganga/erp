Current inspection used ERP `2f4137bd` / UI `9c56b492`; these pending integration products are not published main or production activation. ## M7A commercial-terms gate before first schema/API

Include supplier quotation reference/date, explicit Unspecified/Fixed/OpenEnded validity, offered payment terms, warranty/delivery, exact goods-only discounts, declared Inclusive/Exclusive quoted tax and multiple actual Core document-version selections in the first adopted M7A field map and immutable revision contract. See section 12 of the [M7A specification](../features/PROC-06-M7A-PRINCIPAL-SUPPLIER-QUOTATION-DRAFTS.md). Pure contracts/tests are a design checkpoint only: no EF model, migration, route or live integration is implied. Coordinate a single current-model schema containing commercial fields and retained contact/quote-version/command sidecars; do not migrate the narrow P30 price panel first and label its omitted commercial fields complete.

Core PaymentTerms/purchase-tax catalog implementation is currently unavailable in the inspected backend: existing reference strings are not catalog authority, and HRM payroll tax slabs are unrelated. Preserve supplier-offered documentary values, keep future references explicitly unresolved, and reuse an owning Core service when implemented. Core Documents selection/use contracts exist, but actual scoped document resolution/pinning still needs its owning adapter. M7B owns formal submission, sealing/opening and validity enforcement; it must consume complete explicitly adopted commercial terms rather than first introducing offer storage.

## Reuse boundaries

Held ERP `codex/p30-rfq-quote-recovery-created` (`8d246341`) includes `ProcurementPrincipalSourcingManualQuoteRoutes.cs`, `PrincipalManualQuotationSnapshot.cs`, contact/quote-version records and tests. Held UI `codex/p30-integrated-principal-ui` includes contact and quotation sections in `PrincipalPublication.tsx`. Compare and port narrowly onto the accepted current baseline; do not import their unrelated runtime, migrations or snapshots. In particular, repair early new-work flag gates that would hide original-key quote recovery, and use human supplier labels rather than raw IDs.

Held `codex/p38-award-foundation-current` (`98609167`) contains substantial P32/P36/P38 domain/Core workflow, persistence and test material, but also mixed Contract/Invoice/Receiving changes. Held `codex/p38-principal-award-source` (`43d72640`) adds source qualification. Their presence does not establish a registered, accepted award command or PO consumer. Never put a P36 recommendation or principal P38 ID into the legacy worker-era `SourcingAwardId` FK.

## Execution and release controls

Finish the current M6 acceptance/cleanup and release its source freeze before new product changes. Review M7A's 28-section decisions first, then implement one bounded owning transaction and preserved UI flow. Scaffold genuine migrations from the resulting **current** EF model; never replace the model snapshot with an old held branch. Reuse Core services and ERP components rather than duplicating identity, approval, supplier or currency masters.

Each milestone needs scoped server tests, negative/retry/concurrency tests, meaningful production-path staging tests, native retained-data and finite-role proof, normal-cookie Playwright, independent owner reconciliation, cleanup and documented release review. Keep failed attempts and distinguish local/mock/native/production claims. An absent Finance module does not remove procurement workflows, but Finance still owns ledger/bank execution. Whole Procurement UAT also retains its [other gaps](PROCUREMENT-UAT-AND-GAPS-20261027.md); completing M7 does not silently complete portal, contracts, recurring purchases, returns, documents, transport or analytics.
