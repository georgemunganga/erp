# P26 nullable evidence CHECK correction

Status: isolated source fix; no SDK/model test/PostgreSQL/migration generation or production job run. Root owns central P26 generation and rehearsal. This commit is separate from frozen browser-fixture source f975acf/a182d9b.

PostgreSQL accepts a CHECK evaluating to NULL. An execution1 result with a missing nullable SHA could therefore satisfy the old check as unknown, and Verified exposure with missing owner SHA had the same hole. Nullable columns must remain available to legacy execution0 and Unknown/Stale exposure, so making the whole column NOT NULL would break compatibility.

The conditional result check now explicitly requires nonnull original/input/evidence/policy-rule hashes and lower64hex format for all four. It also requires EvidenceJson and SourceWatermarksJson nonnull inside execution1 only. Producer audit: ProcurementInvoiceMatchingCommands.Compare sets both for every Blocked/Compared result before AddScoped; Foundation.Finish always serializes evidence, and InvoiceMatchExecutionEvidence.SourceWatermarks always serializes the pinned input/review/source envelope. Ordinary safe summary and current claim verification already consume them. No producer/no-provider path legitimately emits a current result without these records. This change does not certify arbitrary nonnull JSON or replace application digest/ownership validation.

Verified exposure explicitly requires OwnerEvidenceSha256 IS NOT NULL before its regex. Existing required reference/watermark/valid-until guards remain. Legacy execution0 and non-Verified nullable owner evidence remain unchanged; no backfill, threshold, owner provider, ledger or authority is invented.

Two authored design-model tests assert the explicit conditional predicates while proving all six current-evidence fields and the owner SHA column remain nullable for compatibility. The actual --matching probe adds otherwise-valid real Blocked-result controls and a rollback-only complete synthetic Verified exposure envelope; this is raw constraint setup, never an authenticated Finance provider or a persisted claim.

Each required field is nulled one at a time in its own owner transaction, requiring SQLSTATE23514 and the exact named check. Six result nulls, malformed policy SHA and four exposure nulls are exercised. Positive controls execute first; legacy execution0 with nullable hashes/JSON and Unknown exposure with null owner fields must succeed. Every mutation rolls back, and a before/after persisted snapshot verifies result/exposure/claim/AP/payment data unchanged. The synthetic Verified envelope is never passed to a domain command or exposed as trusted history. Root must run these authored cases against generated P26 DDL; no passed/runtime claim is made here.
