## Minimum P30 client adapter

Create `src/platform/procurement-sourcing-publication-api.ts` with typed, schema-2-only reads and commands. Reuse `procurementScopeHeaders`, cookie credentials, `cache:no-store`, current abort and context-epoch patterns, and exact decimal string parsing. Never convert quoted money to `Number` or merge worker/principal receipt types.

| Existing UI placement | Actual route and payload | Required behavior |
| --- | --- | --- |
| Principal list and detail | `GET /api/procurement/v1/sourcing/principal-publications` and `GET /{eventId}/principal-publication` | Use the new verified P30 reads for Review/Published and retained Draft/Cancelled. Detail exposes pinned policy/Core case, exact PR lines with **Reserved** allocation, and invitation states. A row with failed evidence stays `Unavailable` and has no action. |
| Reviewer's task queue | `GET /api/procurement/v1/sourcing/principal-publication-reviews/assigned?page=1&pageSize=25` | The server joins current Core pending assignments to RFQ company/branch scope before count/page. Show only verified assigned reviews; an unavailable evidence row has no decision control. |
| Original Bidding Preferences shortlist picker | `GET /api/procurement/v1/sourcing/{eventId}/principal-publication-suppliers?q=...&page=1` | Requires buyer's current `procurement-sourcing-submit` action and owned Draft. Search is at least two characters; the server applies current approval/orderability/qualifications before count/page and returns supplier ID, display name and number only. No generic vendor-admin permission or bank/contact data. |
| Draft detail primary action | `POST /{eventId}/principal-publication-reviews` with `expectedEventVersion`, `originalDraftFingerprint`, selected `supplierIds`, UUID `Idempotency-Key` | Label **Request publication review**. Show policy coverage and actual approved suppliers before submitting. The response means a Core case was opened; it does **not** mean published or emailed. |
| Assigned review in existing detail/approvals shell | `POST /{eventId}/principal-publication-reviews/{caseId}/assignments/{assignmentId}/decisions` with expected event/case/assignment versions, `Approve/Return/Reject`, reason | Only show an assignment after a scoped read proves the current Core principal is named and pending. Approve may remain Pending for parallel/multiple stages. A final Approved result means **internally Published**, with shortlist rows only `ReadyForManualDelivery`. |
| Invitation row in Related | `POST /{eventId}/principal-invitations/{invitationId}/manual-contact` with channel (`EmailOutsideSystem`, `Physical`, `Telephone`, `Other`), external reference and reported time | Label **Record manual supplier contact**. Show the recorder's report, never “email sent by ERP” or portal delivery. The invitation becomes `ManualContactRecorded`; `SentAt` stays empty. |
| Quotation Draft in Related | `POST /{eventId}/principal-manual-quotes`; `GET /{eventId}/principal-manual-quotes`; `GET /{eventId}/principal-manual-quotes/{bidId}`; `PUT` same detail; `POST /{bidId}/cancel`; `GET /{bidId}/versions/{revision}` | Create only after an actual manual contact for an approved invitation. Capture exact quantity/unit price/tax/delivery strings per published line. Revise uses `expectedBidVersion` and the same line set; cancellation retains previous snapshots. Display `totalExact` and **buyer-entered Draft**; never “supplier submitted.” |
| Interrupted command response | `GET /principal-publication-commands/{key}`, `/principal-manual-contact-commands/{key}`, `/principal-manual-quote-commands/{key}` | Store only an actor/scope/action/target/key locator in a **new** P30 journal. On an unknown write, block new POST/key generation and offer explicit GET recovery. Do not persist shortlist IDs, quote prices, reasons, contact references, credentials, or response bodies in browser storage. |

The existing `RfqDetailLayout` **Overview** shows source and policy/case status; **Items** keeps original PR quantities and exact estimates; **Related** shows shortlist, contact status and quotation Drafts; **History** shows only verified Core decisions and append-only P30 version facts. Keep Comments, Terms, Documents, supplier submission, evaluation, award and PO controls visible as unavailable until their own APIs and evidence exist.
