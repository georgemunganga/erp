## Actual HTTP acceptance matrix

Every negative scenario captures scoped business/source/ledger/receipt/audit/outbox state before and after; ordinary denied/no-effect requests must leave it equal. Use separate fresh fixtures for raw corruption/permission/forced-failure exercises; retain initial failed logs and revert synthetic changes explicitly, not production data.

1. **Default-off/absent schema/privilege:**503 before store effects, including when Enabled/connection are configured. A real removed or wrong-shape constraint/index/column privilege fails readiness; no constant-ready production provider.
2. **Real approved competitive source:** actual create→submit→Finance check→open Core approval→real One/All decisions; inspect retained policy Match with exact RFQ code/count and source identities. Draft/unapproved/rejected/withdrawn/stale source denies downstream create.
3. **Partial/consolidated holds:** sourceA approves10units, sourceB4units, same company/branch/currency/method. E1 reserves A3+B2; E2 reserves A2. Expect AAllocated5/BAllocated2, three exact existing allocation rows, no Ordered/Accepted/Finance change. One event can contain lines from different PRs; one PR with multiple selected lines must advance its context aggregate once per actual save, not once per line.
4. **Cancel conservation:** cancel E1 using its actual event version/original fingerprint/reason releases exactly A3+B2, preserves E2's A2, original evidence/IDs/quantity/value and PendingSourcing route. Cancel E2 leaves both held counters0. No Finance release or stock/AP effects. Unknown/missing/inactive retained owners, swapped event-line, wrong allocation type/ID/value/quantity/version or incomplete history blocks cancellation atomically.
5. **Exact replay/recovery:** same body/key returns byte-identical original status/body, no new event/allocation/effect/receipt. Changed original PRversion/title/quantity/reason under the same key409. After cancellation, old Create key still returns its original historical Draft response; it is not current-state confirmation. 6. **Current scope/person:** loss of action, canonical-worker rebound, alias ambiguity, offboarding, changed selected branch or revoked allowed branch denies new command and old receipt. Same actor with current correct scope can recover. Different owner cannot read/recover/cancel; retained branchA/current headerB corruption cannot expose source/evidence to B. 7. **Current vs historical commercial eligibility:** withdrawing a selected offer or method/current Finance invalidation blocks NEW reservations; original held cancellation and exact authorized history recovery do not rerun today's commercial eligibility. Retained evidence/worker/policy hashes themselves must still verify. No financial provenance is backfilled.

Simultaneous identical UUID/body converges on one event/receipt/effect despite separate attempted server IDs; different body under same key conflicts.
