# BE-01 P24 scoped CSV export backport

This source-only backport implements the bounded Vendor and managed Item CSV contract on the P24 API graph. Its governing 28-section contracts are `PROC-01-VENDOR-CSV-EXPORT.md` and `PROC-04-MANAGED-ITEM-CSV-EXPORT.md` at ERP commit `f32f90866fbb309e636f6611caa84194df33a3a7`. It carries no Procurement model, migration, Domain, Infrastructure, or database change.

The two GET routes reuse their existing list visibility and search/status predicates, use a stable default order across pages, and reject filters beyond `search` and `status`. Each route requires its prior read/manage action and a separately configured export action. The new actions have no bootstrap grants, including the legacy `erp_admin` seed. A true All scope is applied only on the company-master read allowlist, within the caller's current Core company and branch assignments.

Other P24 operational paths retain their prior concrete assigned/default branch resolution when a valid All header is present. This is a compatibility behavior, not company-wide operational All support; that broader scope remains a separate C01 gap. Malformed All and mixed All/location headers are rejected.

CSV is synchronous, capped at 10,000 matching rows, fixed to human-readable whitelisted fields, and contains a UTF-8 BOM with protected quoted cells. A durable metadata-only scoped audit precedes any successful attachment response. The routes expose no bank, tax, contact, price, ID-selection, or import capability. Existing HRM CSV quote behavior is unchanged.

The P24 API also needs the existing shared Core schema startup policy for finite normal-cookie hosts. The prior `Program` unconditionally ran Core migrations through its runtime connection, requiring DDL even after the schema owner had already applied the migration. This backport reuses `CoreSchemaStartup` from the current ERP source: production startup validates model parity and pending migration history without applying DDL; development retains automatic setup; `--apply-migrations-only` remains the explicit owner path. An explicitly set `ERP:Database:MigrateOnStartup` continues to control that choice. This changes Core startup only; it grants no new role privileges and does not activate export.

The DB05 private cohort reached real scoped CSV export, then found that Core logout inherited the strict HRM workforce default policy. The current ERP already has a narrower shared authenticated-session policy for the caller's own logout and password change. This backport reuses that policy and its mapped HTTP tests. Anonymous, expired, revoked and inactive sessions stay denied; HRM routes retain their workforce policy and Core administration retains its separate admin policy. Procurement-only users gain no HRM access or new export grant.

**Status:** the earlier P24 source passed its SDK suite; DB03 and DB04 fixture/startup failures and the DB05 logout failure are preserved. This new session-policy source has not been rebuilt or run. A fresh private normal-cookie cohort and independent audit reconciliation remain pending separate acceptance. No production export capability is asserted by this document.
