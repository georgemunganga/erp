# Document evidence gates for P31 and P32

**Status:** Source boundary, 25 October 2026. This note does not change policy, enable a route, grant a role, or claim scanner acceptance. The separate [Manus Core scanner task](../../collaboration/manus/MANUS-CORE-DOCUMENT-SCANNER-04.md) remains `READY_UNACKNOWLEDGED`; its ownership and published baseline stay as assigned there.

| Workflow | Current source contract | What runs without a newly uploaded file |
|---|---|---|
| Ordinary Procurement draft CRUD | Feature-specific scope and permissions apply. Draft creation alone makes no Clean or document-use claim. | Existing draft CRUD remains available where its own readiness and authority pass. C04 is not a blanket prerequisite. |
| P32 commercial draft and Prepare | [Preparation](../../../backend/hrm-api/src/Mightyfin.Erp.Hrm.Api/ProcurementRfqCommercialPreparation.cs) routes an empty requirements set through the owning Procurement/Core transaction without a Core document-use set. [Retained requirements](../../../backend/hrm-api/src/Mightyfin.Erp.Hrm.Api/ProcurementRfqCommercialDocumentUses.cs) accept zero only with `DocumentCount == 0` and no use-set ID; a nonempty set must pass real Core document readiness and retained pin checks. | A zero-document prepared candidate has actual bounded private [draft/Prepare evidence](P32-NATIVE-DRAFT-PREPARATION-ACCEPTANCE-20261025.json). It is not a submitted offer, award, or PO. |
| P32 manual surrogate offer and downstream close/open/P36 recommendation | [Commercial round policy](../../../backend/procurement-api/src/Mightyfin.Erp.Procurement.Application/PrincipalRfqCommercialRoundPolicyRules.cs) currently requires `requireOriginalOfferDocument: true`; a false value is invalid. [SubmitOffer](../../../backend/hrm-api/src/Mightyfin.Erp.Hrm.Api/ProcurementRfqCommercialRoundOffer.cs) requires a nonempty original Core document version, an Available version owned by the sourcing event, and an exact one-version Core document-use set. [Domain submission](../../../backend/procurement-api/src/Mightyfin.Erp.Procurement.Application/PrincipalRfqSealedManualOffers.cs) pins its original version and SHA. Retained offer reads and close/open recheck that use; [P36 source](../../../backend/hrm-api/src/Mightyfin.Erp.Hrm.Api/ProcurementRfqRecommendationDrafts.cs) requires the opened retained offer set and named reader. | A zero-upload, zero-existing-scanned-document cohort cannot submit a structured offer or make a substantive selected-offer recommendation under the current policy. An empty commercial requirements set does not waive the separate original-offer document rule. |
| P31 principal invoice mapping and retained review | [Original-document mapping](../../../backend/hrm-api/src/Mightyfin.Erp.Hrm.Api/ProcurementPrincipalInvoiceMappingRoutes.cs) requires at least one nonempty Core version ID, same physical owner and Available version. [Retained review use](../../../backend/hrm-api/src/Mightyfin.Erp.Hrm.Api/ProcurementPrincipalInvoiceDocumentUses.cs) requires matching nonretired Available versions and Core use pins. | Ordinary manual Received bill capture is a distinct draft; it is not a positive P31 qualified review, AP posting, or payment. No fileless P31 positive is inferred. |

[Core document use](../../../backend/core-api/src/Mightyfin.Erp.Core.Documents.Domain/DocumentUsePin.cs) requires a matching completed **Clean** scan with content hash, scanner engine, definitions and time evidence before a version can be pinned. An Available flag, test fixture, or fabricated document use cannot replace a real scanner result. A private positive cohort with no already genuinely scanned original offer or invoice therefore needs the real C04 scanner dependency and subsequent Core Document owner/API proof. A previously genuine Available version would still require its current owner, scope, purpose, finite-role and retained-evidence checks; C04's direct adapter proof is not itself Procurement HTTP acceptance.

No change to the P31 invoice controls or the P32 original-offer policy is proposed here. A document-free submitted surrogate offer would need a separately approved, versioned business policy and evidence model before implementation; it is not an existing configuration switch.
